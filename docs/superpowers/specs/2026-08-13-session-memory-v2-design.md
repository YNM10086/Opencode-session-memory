# Session-Memory Skill v2 设计 — 踩坑记录与工作流记录

日期：2026-08-13
状态：已确认（用户逐节审批通过）

## 背景

session-memory skill 已运行数月，记录了项目概况、已完成工作、待办，但缺少两类高价值信息：

1. **踩坑经验** —— 踩过的坑及解决方法，跨项目可复用
2. **工作流** —— 项目的固定产出方式与清晰可见的结构

记录这两类信息可显著提升后续工作效率。

## 目标

- 新增**全局踩坑知识库**（跨项目共享、结构化条目、去重）
- 新增**项目内工作流板块**（随 `_session_context.md` 恢复、几行到十行）

## 关键决策

| 决策点 | 结论 |
|--------|------|
| 踩坑记录共享范围 | 全局共享（跨项目） |
| 踩坑触发方式 | AI 自动识别 + 用户手动标记 |
| 踩坑条目格式 | 结构化（现象/根因/解决/技术/来源/日期） |
| 工作流记录位置 | 项目内 `_session_context.md`，不全局共享 |
| 工作流内容 | 结构地图 + 产出流程 |
| 知识库组织 | 全局单文件，每次启动全量读取 |
| 知识库路径 | `.session-memory-config` 配置，默认 skill 目录 |

## 1. 全局踩坑知识库文件

**新增文件 `opencode_knowledge.md`**（与现有 `opencode_usage.md` 命名风格一致）：

```markdown
# Opencode 全局知识库

## 踩坑记录
### <技术/主题1>
- 现象/报错：<原始报错或现象描述>
  根因：<为什么发生>
  解决：<具体解法，含命令/配置>
  技术：<涉及技术栈/语言>
  来源项目：<哪个项目踩的> | 日期：<yyyy-mm-dd>
### <技术/主题2>
...
```

**配置**：`.session-memory-config` 新增 `global_knowledge_path`，默认 `{skill_dir}/opencode_knowledge.md`，与 `usage_tracking_path` 同模式。

## 2. 踩坑记录规则

### 触发条件（纳入 Real-Time Auto-Update 触发表）

| 触发 | 例子 |
|------|------|
| AI 检测到反复报错/多次调试 | 同一错误重试 2 次以上 |
| 异常的解决方法 | 常规解法无效，最终找到非常规解法 |
| 修复了重大 bug | 花较长时间 root-cause 后解决 |
| 用户手动标记 | 用户说"记住这个坑"、"记一下" |

### 结构化条目

- 现象/报错：原始报错或现象描述
- 根因：为什么发生
- 解决：具体解法，含命令/配置
- 技术：涉及技术栈/语言
- 来源项目 + 日期

### 去重机制

记录前搜索知识库同主题条目——已存在且是同一问题的更新解法，则**更新原条目**而非新增；确属新坑才追加。

### 归类

按涉及技术归入 `## 踩坑记录` 下对应技术小节；无匹配小节则新建。

## 3. 项目工作流板块

### 触发条件

| 触发 | 例子 |
|------|------|
| 同一操作模式重复出现 2 次以上 | 每次做 PPT 都先跑某个生成脚本 |
| 项目结构清晰、值得沉淀 | 大项目目录多，每次都要重新探索 |
| 固定产出流程成形 | 前端项目：dev → 截图 → 识图检查 → 循环 |
| 用户手动标记 | 用户说"把流程记下来" |

### 模板更新

`_session_context.md` 自动创建时含 4 个板块：

```markdown
# {项目名} — 会话记忆

## 项目概况
## 工作流
## 已完成的工作
## 待办/待讨论
```

`## 工作流` 板块内容：

```markdown
## 工作流
- 技术栈/入口：<主要技术、启动命令>
- 结构地图：<目录树要点、各模块职责、关键文件位置>
- 产出流程：<步骤 1. 命令 2. 检查点 3. 产出物……>
- 常见产物位置：<产出文件默认路径/命名规则>
```

通常几行，个别到十行。

### 更新规则

同项目工作流采用**覆盖更新**——流程变化时更新原板块保持最新，关键流程变更原因一句话附注保留。

## 4. 与现有机制整合

### 启动流程（Trigger 扩展）

1. 检查/读取 `_session_context.md`（含工作流板块，直接恢复）
2. 创建项目文件（如不存在）
3. 更新使用记录
4. **读取全局知识库 `opencode_knowledge.md` 全量**（新增）

### 写入分工

- `_session_context.md` → 项目进度（已完成/待办/概况）+ **工作流**，保持轻量
- `opencode_knowledge.md` → 跨项目可复用经验（**仅踩坑**），只进不出

### AGENTS.md 同步更新

项目根目录 AGENTS.md 增加"加载后读取全局知识库"步骤，与 skill 指令保持一致（现有模式：skill 指令 + AGENTS.md 双重约束防遗漏）。

### 跳过规则

- 仅问答/闲聊、无结论的研究 → 不记录
- 坑未定位根因（只有现象没解决）→ 不记录

## 不变的部分

- Usage Tracking（追加式日志）
- Auto Project Summary
- Real-Time Auto-Update 框架
- 规则（不询问项目名、静默创建、无占位符）
